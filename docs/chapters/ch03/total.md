# 3.1 引言

C++程序由许多独立开发的组成部分构成，比如函数（§1.2.1）、用户自定义类型（第2章内容）、类的层级（§5.5）以及模板（第7章）。要妥善管理这些复杂的组成部分，关键在于明确界定它们之间的交互关系。首要且最重要的步骤就是区分某个组件的接口与其实现方式。在C++语言中，接口是通过声明来体现的。一个声明就足以说明使用某个函数或类型时所需的一切信息。例如：

```cpp
double sqrt(double);    // 平方根函数接收double参数，返回double值

class Vector {
public:
    Vector(int s);
    double& operator[](int i);
    int size();

private:
    double* elem;   // elem指向一个数组，该数组承载sz个double
    int sz;
};
```
这里的要点是：函数体(函数的定义)可以放在“其他地方”。在这个例子中，我们希望`Vector`的定义也放在“其他地方”，不过这个问题我们稍后再讨论（抽象类型；§5.3）。`sqrt()`的定义如下：

```cpp
double sqrt(double d)   // sqrt()的定义
{
    // ... 数学课本里的算法 ...
}
```

对于`Vector`来说，我们需要定义全部三个成员函数：

```cpp
Vector::Vector(int s)               // 构造函数的定义
    :elem{new double[s]}, sz{s}     // 初始化成员变量
{
}

double& Vector::operator[](int i)   // 取下标运算符的定义
{
    return elem[i];
}

int Vector::size()                  // size()的定义
{
    return sz;
}
```

我们必须自行定义`Vector`相关的函数，而`sqrt()`则不必如此，因为它属于标准库的组成部分。不过，这其实并没有什么区别：所谓“标准库”，不过是用与我们相同的编程语言编写而成的“其他代码”罢了。

一个实体，比如一个函数，可以有多个声明方式，但定义却只能有一个。

# 3.2 分离编译

C++支持“分离编译”的机制，即用户代码只能看到所使用的类型和函数的声明部分。实现这种方式有两种途径：

- 头文件（§3.2.1）：将各种声明放在单独的文件中，这些文件就被称为头文件。在需要使用这些声明的地方，通过`#include`指令引入相应的头文件即可。
- 模块（§3.2.2）：定义模块(`module`)文件，将其单独编译，然后在需要时导入(`import`)该模块到其他地方。只有那些被明确导出的变量或函数，才能被导入该模块的代码所使用。

这两种方式都可以将程序拆分成一组相互独立的代码片段。这种划分方式有助于缩短编译时间，同时也能确保程序中各个逻辑上独立的组成部分彼此分离，从而降低出错的可能性。所谓“库”，通常指由多个单独编译而成的代码片段组成的集合，比如各种函数。

使用头文件来组织代码的做法可以追溯到C语言的早期阶段，至今仍是最为常见的编码方式。而模块化的用法则是C++20的新特性，它在提升代码的可维护性及编译效率方面有着显著的优势。

## 3.2.1 Header Files

通常，我们会将用于指定某段代码所对应接口的声明，放在一个与其用途相对应的文件中。例如：

```cpp
// Vector.h:

class Vector {
public:
    Vector(int s);
    double& operator[](int i);
    int size();
private:
    double* elem;   // elem指向一个数组，该数组承载sz个double
    int sz;
};
```

C++ 支持分离编译，允许将程序分割成多个源文件。用户代码通常放在 `.cpp` 文件中，而接口声明则放在 `.h`（头文件）中。这种分离使得我们可以独立编译各个源文件，最后再将它们链接成一个可执行程序。

### 3.2.1 分离编译的优势 {#3.2.1}

分离编译带来了几个重要优势：

- **更快的编译速度**：修改一个文件后，只需重新编译该文件及其依赖，而不必重新编译整个程序
- **逻辑组织**：将相关功能放在同一个文件中，使代码结构更清晰
- **代码复用**：同一个源文件可以被多个程序共享

传统上，C++ 使用 `#include` 指令来包含头文件。例如：

```cpp
#include <iostream>            // 包含 I/O 流库的声明

int main()
{
    std::cout << "Hello, World!\n";
}
```

`#include` 本质上是一个文本复制操作——预处理器将头文件的全部内容复制到 `#include` 指令所在的位置。这种方式简单直接，但也存在一些问题：编译速度慢、宏污染、包含顺序依赖等。

### 3.2.2 分离编译的限制 {#3.2.2}

C++20 引入了*模块*（modules）作为 `#include` 的现代替代方案。使用模块时，我们用 `import` 代替 `#include`：

```cpp
import std;              // 导入标准库模块

int main()
{
    std::cout << "Hello, World!\n";
}
```

模块的优势包括：

- 编译速度显著提升（模块只需编译一次，而非在每个翻译单元中重复编译）
- 更好的封装性（模块可以控制哪些实体对外可见）
- 消除宏污染和包含顺序问题
- 更清晰的依赖关系

不过，截至 C++20，以模块形式提供整个标准库（`import std;`）尚未成为强制标准。如果你的编译器不支持 `import std;`，可以继续使用传统的 `#include <iostream>` 方式。大多数主流编译器（GCC、Clang、MSVC）已在逐步支持模块。

## 3.3 命名空间

随着程序规模的增长，名称冲突的风险也随之增加。不同库可能定义了同名的函数或类。C++ 通过*命名空间*（namespace）来解决这个问题。

命名空间提供了一种将相关名称组织在一起的作用域机制：

```cpp
namespace My_code {
    class complex { /* ... */ };
    complex sqrt(complex);
    // ...
    int main();
}

int My_code::main()
{
    complex z {1, 2};
    auto z2 = sqrt(z);
    std::cout << '{' << z2.real() << ',' << z2.imag() << "}\n";
    // ...
}

int main()
{
    return My_code::main();
}
```

通过将代码放入命名空间 `My_code`，我们可以确保其中的名称不会与其他命名空间中的同名实体发生冲突。

要访问命名空间中的名称，可以使用作用域解析运算符 `::`：

```cpp
My_code::complex c {1, 2};
My_code::sqrt(c);
```

如果某个名称被频繁使用，可以通过 `using` 声明将其引入当前作用域：

```cpp
using My_code::complex;
complex c {1, 2};   // 现在可以直接使用 complex
```

也可以使用 `using namespace` 指令将整个命名空间中的所有名称引入：

```cpp
using namespace My_code;
complex c {1, 2};   // 所有 My_code 中的名称都可见
```

不过，`using namespace` 应谨慎使用——尤其是在头文件中——因为它会破坏命名空间提供的隔离效果。在 `.cpp` 文件中使用 `using namespace` 通常是安全的。

标准库中的所有名称都位于 `std` 命名空间中。这就是为什么我们写 `std::cout` 而不是 `cout` 的原因。

## 3.4 函数参数和返回值

函数是代码模块化的基本单元。理解参数如何传递以及返回值如何返回，对于编写正确且高效的 C++ 代码至关重要。

### 3.4.1 参数传递

默认情况下，C++ 使用*按值传递*（pass by value）——函数获得的是实参的一份副本：

```cpp
void f(int x) { x = 42; }   // 修改的是局部副本，不影响调用者

int a = 7;
f(a);                       // a 仍然是 7
```

对于大型对象，按值传递可能代价高昂。此时可以使用*引用传递*（pass by reference）：

```cpp
void g(int& x) { x = 42; }  // 修改的是原始对象

int a = 7;
g(a);                       // a 现在是 42
```

如果不想让函数修改实参，可以使用 `const` 引用：

```cpp
void h(const int& x) { /* 可以读取 x，但不能修改 */ }
```

对于小对象（如 `int`、`double`、指针），按值传递通常是最佳选择。对于大型对象，使用 `const` 引用可以避免不必要的拷贝。

### 3.4.2 返回值

函数可以通过返回值将结果传回调用者。与参数传递类似，返回值默认也是按值返回的：

```cpp
string compose(const string& name, const string& domain)
{
    return name + '@' + domain;
}

string addr = compose("greeting", "example.com");
```

现代 C++ 编译器会通过*返回值优化*（Return Value Optimization，RVO）和*移动语义*（move semantics，[§6.2.2](../ch06/6-2-copy-move.md)）来避免不必要的拷贝，因此按值返回通常非常高效。

### 3.4.3 结构化绑定

C++17 引入了*结构化绑定*（structured bindings），允许从函数返回多个值：

```cpp
struct Entry {
    string name;
    int value;
};

Entry read_entry(istream& is)
{
    string s;
    int i;
    is >> s >> i;
    return {s, i};
}

auto [name, value] = read_entry(cin);
cout << name << " = " << value << '\n';
```

结构化绑定使得处理多返回值变得简洁而优雅。

# 3.5 建议

[1] 区分声明（用作接口）与定义（用作实现）；§3.1。
[2] 在支持模块的地方，优先使用模块而非头文件；§3.2.2。
[3] 使用头文件表示接口并强调逻辑结构；§3.2；[CG: SF.3]。
[4] 在实现其函数的定义文件中 `#include` 该头文件；§3.2；[CG: SF.5]。
[5] 避免在头文件中进行非内联函数定义；§3.2；[CG: SF.2]。
[6] 使用命名空间表达逻辑结构；§3.3；[CG: SF.20]。
[7] 将 using 指令用于过渡、基础库（如 `std`）或局部作用域；§3.3；[CG: SF.6] [CG: SF.7]。
[8] 不要在头文件中使用 using 指令；§3.3；[CG: SF.7]。
[9] 按值传递“小”值，按引用传递“大”值；§3.4.1；[CG: F.16]。
[10] 优先使用 const 引用传递，而非普通引用传递；§3.4.1；[CG: F.17]。
[11] 通过函数返回值返回结果（而不是通过输出参数）；§3.4.2；[CG: F.20] [CG: F.21]。
[12] 不要过度使用返回类型推导；§3.4.2。
[13] 不要过度使用结构化绑定；具名返回类型往往使代码更易读；§3.4.5。
