# 4.1 引言

错误处理是一个庞大而复杂的话题，其关切与影响远不止语言设施本身，还延伸到编程技术与工具。不过，C++ 提供了一些辅助特性。最主要的工具其实是类型系统本身。我们不是辛辛苦苦地只用内置类型（例如 `char`、`int` 和 `double`）和语句（例如 `if`、`while` 和 `for`）堆砌应用，而是构建适合应用的类型（例如 `string`、`map` 和 `thread`）和算法（例如 `sort()`、`find_if()` 和 `draw_all()`）。这类更高层的构造简化了编程，限制了出错机会（例如，你不太可能对一个对话框去做树遍历），也提高了编译器抓住错误的机会。C++ 语言的大部分构造，都致力于设计并实现优雅而高效的抽象（例如用户定义类型以及使用它们的算法）。使用这类抽象的一个效果是：运行时错误能被检测到的位置，与它能被处理的位置，往往彼此分离。随着程序增长——尤其是大量使用库时——错误处理的标准就变得重要。在程序开发的早期就明确一套错误处理策略，是个好主意。
