# 4.3 不变式

用异常来报告越界访问，是函数检查其实参、并因基本假定（前置条件）不成立而拒绝执行的一个例子。若我们形式化地规定 `Vector` 的下标运算符，会说类似“下标必须在 `[0:size())` 范围内”这样的话，而这正是我们在 `operator[]()` 中所测试的。`[a:b)` 记法指定半开区间，表示 `a` 属于该范围，而 `b` 不属于。每当定义函数时，都应考虑它的前置条件是什么，以及是否要测试它们（[§4.4](4-4-alternatives.md)）。对大多数应用来说，测试简单的不变式是个好主意；另见 [§4.5](4-5-assertions.md)。

然而，`operator[]()` 操作的是 `Vector` 类型的对象；除非 `Vector` 的成员具有“合理”的值，它所做的一切都没有意义。特别是，我们确实说过“`elem` 指向含有 `sz` 个 `double` 的数组”，但那只写在注释里。这种关于对某个类假定为真的陈述，称为*类不变式*（class invariant），或简称*不变式*（invariant）。构造函数的职责是为其类建立不变式（以便成员函数可以依赖它），而成员函数的职责是确保在退出时不变式仍然成立。遗憾的是，我们的 `Vector` 构造函数只部分完成了工作。它正确初始化了 `Vector` 的成员，却没有检查传给它的实参是否合理。考虑：

```cpp
Vector v(-27);
```

这很可能造成混乱。

下面是一个更恰当的定义：

```cpp
Vector::Vector(int s)
{
    if (s<0)
        throw length_error{"Vector constructor: negative size"};
    elem = new double[s];
    sz = s;
}
```

我用标准库异常 `length_error` 来报告元素个数为负，因为一些标准库操作也用该异常报告这类问题。若 `operator new` 找不到可分配的内存，它会抛出 `std::bad_alloc`。现在可以这样写：

```cpp
void test(int n)
{
    try {
        Vector v(n);
    }
    catch (std::length_error& err) {
        // ... 处理负数大小 ...
    }
    catch (std::bad_alloc& err) {
        // ... 处理内存耗尽 ...
    }
}

void run()
{
    test(-27);                  // 抛出 length_error（-27 太小）
    test(1'000'000'000);        // 可能抛出 bad_alloc
    test(10);                   // 很可能没问题
}
```

内存耗尽发生在你请求的内存超过机器所能提供，或程序几乎已用尽可用内存而你的请求把它推过上限时。注意，现代操作系统通常会给你比能同时装进物理内存更多的空间，因此请求过多内存可能在触发 `bad_alloc` 之前很久就造成严重变慢。

你可以定义自己的类用作异常，并让它们携带从检测到错误的位置到可以处理错误的位置之间所需的或多或少的信息（[§4.2](4-2-exceptions.md)）。不必使用标准库的异常层次结构。

常常，在异常抛出之后，函数已无法完成其分派的任务。此时，“处理”异常意味着做一些最少的局部清理，然后重新抛出异常。例如：

```cpp
void test(int n)
{
    try {
        Vector v(n);
    }
    catch (std::length_error&) {     // 做些事并重新抛出
        cerr << "test failed: length error\n";
        throw;      // 重新抛出
    }
    catch (std::bad_alloc&) {         // 糟糕！本程序未设计为处理内存耗尽
        std::terminate();       // 终止程序
    }
}
```

在设计良好的代码中，`try` 块很少见。通过系统使用 RAII 技术（[§5.2.2](../ch05/5-2-concrete-types.md#5.2.2)、[§6.3](../ch06/6-3-resource-mgmt.md)）来避免过度使用。

不变式的概念对类的设计至关重要，而前置条件在函数设计中起着类似作用：

- 表述不变式有助于我们精确理解自己想要什么。
- 不变式迫使我们具体化；这使我们更有机会把代码写对。

不变式的概念也支撑着 C++ 由构造函数（[第5章](../ch05/index.md)）和析构函数（[§5.2.2](../ch05/5-2-concrete-types.md#5.2.2)、[§15.2.1](../ch15/15-2-pointers.md#15.2.1)）所支持的资源管理观念。
